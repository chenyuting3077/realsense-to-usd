# 讓 Fast-FoundationStereo 更快：縮小輸入或 max_disp 128

[English](README.md)

即時深度的速度卡在 FFS（depth thread 其他部分約 15 ms）。兩種加速方式，和之前的設定比較
（848x480 IR 補到 864、max disparity 192、TensorRT fp32 + TF32、8 次迭代），Jetson AGX Thor。
**main.py 現在用 636x360。** 用 [`eval_ffs.py`](eval_ffs.py) 重現：

```bash
python -m recon.export_ffs_trt                            # 636x360 補到 640x384（預設）
python -m recon.export_ffs_trt --height 480 --width 864   # 848x480，以及加 --max-disp 128
python -m docs.ffs_speed.eval_ffs output/live_20261012_160515/rec output/live_20261012_171428/rec
```

- 延遲：一組 848x480 IR，模型呼叫（縮圖、正規化、補邊、推論、視差放回 848x480），熱機 10 次後 50 次的平均。
- ETH3D two-view：27 組訓練集，各切 848x480 的窗口（較小的整張），在原解析度上和 non-occluded 雷射掃描 ground truth
  比較。636x360 是縮小後推論、視差再放大回來。
- 推估誤差：把 ETH3D 的 EPE 換成 D455 的深度誤差，z² / (fx · 基線) · EPE，fx 430.6 px、基線 95 mm
  （2.5 m 處每 px 0.15 m，4 m 處 0.39 m）。ETH3D 是可見光影像，不是 D455 帶投射光點的 IR。

D455 的資料沒有 ground truth：下表是各設定和 848x480、max_disp 192 的差異，依它的深度分區間。

差異也包含 848x480、max_disp 192 自己的雜訊，不全是另一個設定的誤差。

## 結論

- **max_disp 128**：快 1.44 倍（10.1 fps），0.35 m 以外的深度一樣（到 5 m 差異中位數 0–10 mm，ETH3D 不變）。
  比 fx · 基線 / 128 = 0.32 m 更近的地方配對不到，但仍會輸出深度、偏遠約 7 cm：這些深度要丟掉（視差接近 128）。
  桌面上約 0.3 m 的近拍會沒有深度。
- **636x360**：快 1.75 倍（12.3 fps）。距離越遠越不準：ETH3D EPE 多 10%；D455 上和 848x480 的差異中位數
  2–3 m 是 2.3 cm、3–4 m 是 5 cm、4–5 m 是 8 cm（p90 35–84 cm：邊緣與遠處、紋理弱的地方）。近距離沒有損失。
- 即時地圖（深度 ≤ 2.5 m）兩者都可以用；最終 mesh 用到 4 m，max_disp 128 保住遠處的精度。
  main.py 用 636x360：最快，近拍也不會沒有深度。
